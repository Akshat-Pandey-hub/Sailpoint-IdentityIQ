# SailPoint IdentityIQ — Data Requirements for the 16 POC Use Cases

**Purpose:** the authoritative list of what each POC use case needs from SailPoint IdentityIQ — source objects, tables, fields, and records.

> **Naming note:** `kf_*` names are **KeyForge extraction tables that represent IIQ source objects**. They are not the underlying (undocumented) IIQ database table names. Each is populated read-only from the native IIQ Java API (`source_interface = native_iiq_java_api`), kept separate from the REST/SCIM baseline.

### Cross-cutting source facts (used by many UCs, all extracted)
- **Entitlement metadata** (`kf_entitlement`): id, application, attribute, value, type, description + per-locale descriptions, owner, requestable, `iiqElevatedAccess` (privileged), classifications-as-attributes.
- **Approval configuration evidence** (`kf_workflow_definition`): full step → nested-approval → WorkItemConfig tree, preserving static owner vs dynamic ownerScript/ownerSource and the workgroup flag on each approver — captured as **evidence only** (rules never evaluated, Level 1/2 never inferred from position).
- **Account/orphan facts** (`kf_account`): identity correlation, manually-correlated flag, disabled/locked, entitlement presence.
- **Provenance chain**: `kf_identity_role` (ASSIGNED/DETECTED), `kf_role_entitlement`, `kf_role_hierarchy`, `kf_identity_request`(+item/approval), `kf_provisioning_txn`/`kf_provisioning_item`.
